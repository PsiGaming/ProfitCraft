# ProfitCraft: work log

What was done and when, newest first. `FEATURES.md` describes what ProfitCraft does now and what is planned; `DESIGN.md` how it is built. Everything that is history (releases, fixes, replaced designs, decisions that were later changed) is here.

All releases are GitHub pre-releases at github.com/PsiGaming/ProfitCraft. Version names: `0.1-alpha.0` style until `0.3-beta.0`; three numbers since 2026-11-19 (`0.3-beta.0` counts as 0.3.0). Zip names: `ProfitCraft-v<version>-forever.zip` up to `v0.2`, without the `v` from `0.3-beta.0` on.

## 0.4.0-beta.9 (2026-11-24): shipped list of items no merchant takes, quieter "!", gap above settings headings
- The author (beta.8, in game): settings window improved, but the yellow headings sat too close to the row above. A heading now takes a full row with 10 px above its text (was 0.8 row, 4 px); window 700 x 628.
- **Where a list of unsellable items comes from** (the author asked): wago.tools exports Forever's game data tables (product `wowf`, build 1.60.1.71091). In `ItemSparse`, Blinding Powder has a sell price (125c) and bit `0x1000` of `Flags_1`, which ordinary sellable goods lack; 328 items have both. The author expected enchanting dust to be vendorable, but the data flags Strange Dust too; a Strange Dust the author bought was learned as unsellable at once (bag `hasNoValue`), which confirmed the flag on a second item. So ProfitCraft now ships the list (`Sources/NoVendorValue.lua`, generated by `plan/tools/no_vendor_value.py`), a block list rather than a list of safe items (the same information, 328 entries instead of about 19,000). Bags overrule it.
- **Orange "!" less intrusive** (the author chose it from my recommendation): the game data now counts as verification, so the "!" and the "not verified" notes only show for items with an ID above the highest in the data (291874; newer than the list) that were never carried. Before, every item never carried had it, which would have trained the author to ignore it.
- Addon API checked for a way to ask by item ID (the author asked): none. Forever's API docs (1.60.1) have `sellPrice` only in item info; the one no-value field is `hasNoValue` on bag-slot info.
- Tests: 512 checks + 18 without Auctionator.

## 0.4.0-beta.7 (2026-11-24): live prices from browse searches, recipe clicks the way Blizzard's list does it
- **Confirmed in game** (2026-11-24): price updates from Auctionator's Shopping tab happen immediately, and clicking a recipe in the profit list selects it immediately. Not yet reported: whether Blizzard's Create button still works after a ProfitCraft click.

## 0.4.0-beta.6 (2026-11-24): verified vendor prices, live search prices, recipe clicks while loading, settings layout
- The author: "are you going to fix this vendor bug that just cost me 2G?" beta.5 only limited the damage (learning after the fact, the 1g cap); the cause was trusting the item data's vendor price, which nothing on Forever lets an addon check for an item not in the bags. First fix tried (built, not released): buy unverified items only as a test of 1 unit. **Rejected by the author** ("buy one single item of every single item I ever come across? No."). Built instead: an account-wide verified list from bags and bank (every character), and a warning ("!", tooltip, dialog note) on unverified Vendor finds; buying isn't blocked. Researching a shipped list of items no merchant takes stays open.
- **Settings window**: 10 px padding; long pages flow into two columns (Opportunities ran off the window).
- **Clicking a recipe in the profit list did nothing for 10-20 s after opening a profession** (the author; since 0.3 at least). ProfitCraft's click code (`C_TradeSkillUI.OpenRecipe`) unchanged since 0.1, Blizzard's profession window code unchanged since 2026-11-02 (Gethe/wow-ui-source history); Blizzard sets the request aside while `C_TradeSkillUI.IsDataSourceChanging()` is true. Now a click while loading is kept and sent once loading is done, with a status line. Whether the game was really still loading is unconfirmed (the author can run `/run print(C_TradeSkillUI.IsDataSourceChanging())` during the dead time).
- Also in this release: the `hasNoValue` confirmation in the docs and one code comment.
- **The profit list ignored fresh search prices** (Bolt of Mageweave +28s per stack in the list, but after Auctionator's Search the recipe details said -58c per craft). Cause: on a same-day tie ProfitCraft's scan data wins over Auctionator's (whose age is only in whole days), so the morning's full scan beat the fresh search. Now ProfitCraft reads the results of any single-item AH search itself (live prices), and the newer of those and the full scan counts.
- Tests: 497 checks + 17 without Auctionator.

## 0.4.0-beta.5 (2026-11-24): spend protection, items no merchant takes, filters, buying during a scan
- The author (beta.4): right-click buying didn't work during a quick scan (it was refused on purpose, to keep one AH job at a time), so a good find could be gone before the scan ended. Now buying and left-click work during the scan; the scan pauses while the buy dialog is open and carries on when it closes.
- **Loss in game:** the author bought 200 Blinding Powder for 2.4g (1s 24c each; item data and Auctionator's "Vendor" line: 1s 25c), most of the character's money; the merchant refused it ("doesn't want this item"). The vendor safety checks couldn't catch it: the vendor price itself was wrong. Tooltips show no sell price outside a merchant on Forever, so no tooltip check. Built: learning such items (bag "no value" flag, merchant refusals; `/pcraft unsellable`), **max per purchase** (default 1g) and the shared **keep at least** in the settings (the author asked for both).
- **Filters** (188 Rough Bronze Cuirass for 3s total; asked for both options): "Stackable only" checkbox and "Single items: min profit each" (default 10s). Tooltip says whether an item stacks and how far.
- **Confirmed after release** (2026-11-24, Blinding Powder back in the bags): the bag "no value" flag (`hasNoValue`) is `true` for every stack. Recorded in `knowledge/forever-vs-vanilla.md` ("Merchants"). Check used: `/run for b=0,5 do for s=1,C_Container.GetContainerNumSlots(b) do local i=C_Container.GetContainerItemInfo(b,s) if i and (i.hasNoValue or (i.itemName or ""):find("Blinding")) then print(i.hyperlink, i.hasNoValue) end end end`.
- Tests: 484 checks + 16 without Auctionator.
